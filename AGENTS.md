# AGENTS.md

## Проект

Автоповторитель сделок Т-Инвестиций: ACCOUNT/INDEX/COMPOSITE строят планы,
общий исполнитель проверяет их и торгует в пределах разрешений и бюджета.
Описание приложения — в [README](README.md), технических команд —
в [scripts/README](scripts/README.md).

## Порядок работы

1. Выбрать нужный раздел по [индексу инструкций](docs/agents/README.md)
   и прочитать его перед изменением соответствующего кода.
   [Историю находок](docs/agents/history.md) читать адресно для обоснований.
2. Сохранять разделение чистых стратегий, своих DTO/портов, SDK-адаптеров
   и оркестрации. Подготовка и полная валидация планов предшествуют эффектам.
3. Деньги и количества считать в Decimal с точным учётом units/nano;
   соблюдать владение, cash_floor, лотность и собственные немаржинальные лимиты.
4. Подтверждать сделки проверенными фактами брокера; использовать
   безопасные причины ошибок и маскирование credentials в логах.
5. Ручные правки выполнять через apply_patch, сохраняя чужие изменения.
   Новые зависимости согласовывать до добавления.
6. Код проверять pytest по TDD RED -> GREEN; порты мокировать через
   autospec(spec_set=True). Сохранять действующие пороги и область покрытия;
   стремиться к 100% проверенного поведения.
7. Live E2E и рабочие торговые запуски выполнять по отдельному согласованию.
   Песочницу запускать с sandbox-токеном, production — с production-токеном.
8. README поддерживать про текущее состояние; CHANGELOG — кратким по выпускам.
   Историю и обоснования размещать в справочниках, перечисленных в индексе.
   Версии — SemVer X.Y.Z; теги — vX.Y.Z по [процедуре выпуска](scripts/README.md#версии-и-выпуск).

## Проверки

```bash
make lint
make coverage
git diff --check
```

Прогон без покрытия — make test; точечные проверки — pytest выбранного модуля.
Общее и diff-покрытие >=90%; lint строгий. Make выбирает .venv/bin/python,
затем python3; PYTHON задаёт явный интерпретатор.
Параметры окружения и правила untracked diff — в [инструкции проверок](docs/agents/development.md#проверки-и-запуск).
Полный live E2E проверяет конкретный SHA; offline-тесты проверяют другой уровень.

## Деплой и выпуск

Использовать существующий CI, PR и цель make claude-yandex-archive
(build/yandex-function.zip). Защита master требует Lint, Offline checks,
Sandbox E2E для нужного SHA. Деплой проверяется read-only чтением версии функции.
Детали OIDC, yc, runtime SA/Lockbox и ресурсов — в [контракте деплоя](docs/agents/deployment.md).
Результаты деплоя и границы связанных выпусков записывать в
[историю версий](docs/history/versioning.md), не в README приложения.
