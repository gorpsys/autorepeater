# AGENTS.md

Instructions for coding agents working in this repository.

## Что это

Автоповторитель сделок для Т-Инвестиций: приводит счёт назначения (dst) к цели стратегии, выбранной по `algoritm` и `src`, через T-Invest API (`t-tech-investments`). В CLI оба параметра обязательны; облако по умолчанию выбирает COMPOSITE/BALANCED. Алгоритм определяет смысл источника: повторение счёта или расчёт по JSON-конфигу. Локальный цикл использует события позиций через собственный порт данных, облако выполняет разовый пересчёт.

## Команды

Алгоритмы регистрируются по имени, индексные составы выбираются отдельно
по `name` JSON. Для нового состава регистрация Python не нужна.

```bash
pip install -r requirements.txt

# Тесты (pytest, тесты лежат в test/)
pytest test/test_autorepeater.py          # весь файл
pytest test/test_autorepeater.py -k имя_теста   # один тест

# Покрытие: исполняемые строки рабочего кода, включая main.py и handler.py
pip install pytest-cov==7.1.0 diff-cover==10.6.0
pytest --cov --cov-report=term-missing --cov-report=xml
coverage report --fail-under=90
git fetch origin master
diff-cover coverage.xml --compare-branch=origin/master --fail-under=90

# Линтеры (конфигов нет, используются дефолтные настройки CI)
pylint $(git ls-files '*.py')
flake8 . --count --select=E9,F63,F7,F82 --show-source --statistics
flake8 . --count --exit-zero --max-complexity=10 --max-line-length=127 --statistics

# Архив для Yandex Cloud Functions
make claude-yandex-archive
```

CI (GitHub Actions, Python 3.12) гоняет pylint по всем файлам, flake8 и pytest.
Общее линейное покрытие должно быть не менее 90%, покрытие добавленных и
изменённых исполняемых строк — тоже не менее 90%. Пороги проверяются отдельными
шагами, `coverage.xml` сохраняется как артефакт. Область покрытия задана в
`.coveragerc`: рабочий код, включая точки входа; тесты, сборочные копии и
виртуальные окружения не учитываются. Для PR diff сравнивается с SHA базовой
ветки, для push в `master` — с предыдущим SHA push. Diff без исполняемых строк
проходит без расчёта процента. Триггеры сохранены: pytest/покрытие на PR в
`master` и push в `master`, pylint на каждый push. Ошибки проверок делают CI красным.

## Запуск

```bash
export INVEST_TOKEN=...   # токен Т-Инвестиций, читается из окружения
python main.py --algoritm <имя алгоритма> -s <источник> -d <id счёта назначения> \
    [--debug] [-t threshold]
```

`--debug` рассчитывает заявки без отправки. `threshold` (0.004) проверяется строго
от полной стоимости назначения с деньгами до резервов и распределения.
Резерв берётся только из обязательного поля конфига ACCOUNT/INDEX внутри
стратегии. Флаги `-r`/`--reserve` в приложении и калибраторе отклоняются argparse;
переопределения на запуск нет. COMPOSITE собственного резерва не имеет.

`algoritm` обязателен в CLI и общем селекторе, написание именно такое.
Облачные значения по умолчанию описаны ниже. Имя выбирается в `ALGORITHMS`,
без автоопределения по виду `src`. ACCOUNT сам требует строку ASCII-цифр,
сохраняя ведущие нули; INDEX и COMPOSITE ищут точное `name` собственного JSON,
включая цифровое имя.
Имена источников независимы от имён алгоритмов и могут совпадать с ними.
Регистр и пробелы не нормализуются. Отсутствующее/пустое имя алгоритма вызывает
`ValueError('algoritm is required')`, неизвестное `ValueError('unsupported algoritm: ...')`.
Пустой/отсутствующий `src` вызывает `UnsupportedSourceError('src is required')`;
ошибки источника/конфига также завершают запуск до SDK.
CLI и облако выполняют `prepare_strategy(algoritm, src)` один раз до чтения токена,
передают `PreparedStrategy` в Runner; фабрика и проверка контракта выполняются
до создания Client без повторной подготовки. Примеры:
`python main.py --algoritm INDEX -s IMOEX -d <id> --debug` и
`python main.py --algoritm ACCOUNT -s 001234 -d <id> --debug`.
Значения по умолчанию выше взяты из `constants.py`; старое значение threshold
в CLI help пока не обновлено.

## Архитектура

Код разделён по слоям, точка входа остаётся в `main.py`:

- **`constants.py`** — константы `THRESHOLD`, `IMPORTANT` и настройка точности `Decimal`.
- **`money.py`** — чистые функции для `Decimal`, количества позиций и строкового форматирования денег/инструментов.
- **`portfolio.py`** — чтение назначения `get_portfolio(client, account_id)` без вывода, DTO `TargetPortfolio` и проверка карт количеств/цен `validate_target`; без импорта SDK.
- **`reporting.py`** — пользовательские сообщения, просмотр счетов, форматирование позиций (`postiton_to_string`), поиск инструмента для вывода и `GetInstrumentException`.
- **`account_config.py`**, **`configs/account/account.json`** — обязательный резерв ACCOUNT, путь `ACCOUNT_CONFIG_PATH`, проверка без SDK.
- **`account_strategy.py`** — подготовка номера счёта и настроек; снимок через StrategyData без валют, собственный резерв до ratio, количества/цены, объявление счетов и решение по событию.
- **`index_config.py`**, **`configs/*.json`** — схема, проверка и обнаружение индексных конфигов по полю `name`; встроенный IMOEX содержит 44 бумаги.
- **`index_strategy.py`** — подготовка имени JSON и `IndexStrategy`: собственные метаданные/котировки через порт, чистый `calculate_index_target`, распределение лотов и события назначения.
- **`scripts/check_imoex_strategy.py`** (от корня) — явно запускаемая калибровка без торговли, использует тот же чистый расчётчик.
- **`composite_config.py`**, **`configs/composite/*.json`** — строгая схема долей и ссылок, точный выбор по имени через `COMPOSITE_CONFIG_DIR`.
- **`composite_strategy.py`** — подготовка детей через контекст, непрозрачные снимки, распределение бюджета, общая цель и событийные решения без зависимости от типов детей.
- **`config_catalog.py`** — нейтральный кандидат, однократное чтение/валидация и точный выбор имени с переданной функцией предупреждения; не знает схем, путей, реестра или SDK.
- **`strategy_budget.py`** — общий чистый `available_budget(budget, reserve)` для листовых стратегий и калибратора.
- **`strategy_contract.py`** — четырёхметодный Protocol `Strategy`, `validate_strategy`, `AlgorithmDefinition`, `PreparedStrategy`, `PreparationContext`, нейтральный `create_strategy`, `UnsupportedSourceError`.
- **`strategy_data.py`** — собственные DTO, `InstrumentType`, read-only Protocol `StrategyData`, `DataAccessError`; только стандартная библиотека.
- **`tinvest_strategy_data.py`** — адаптер `TInvestStrategyData`: SDK-чтение, преобразование DTO/units/nano, перевод транспортных ошибок.
- **`strategies.py`** — `ALGORITHMS`, регистрация ACCOUNT/INDEX/COMPOSITE, подготовка дерева с контролем активного пути пар и сохранением фабрик; реестр не разбирает src и схемы файлов.
- **`triggers.py`** — специфичная для счёта проверка событий (`check_triggers`), вызываемая только `AccountStrategy`.
- **`orders.py`** — `OrderParams` и оценка объёма продаж/покупок по отдельным картам цен назначения/цели; используется максимум двух сумм.
- **`repeater.py`** — `AutoRepeater(client, strategy, data)`: проверка контракта, бюджет назначения, проверка цели, расчёт/отправка заявок и общий цикл событий. `sync_accounts` и `mainflow` получают только `dst`; стратегии получают data, исполнение использует client.
- **`runner.py`** — `Runner(token, prepared_strategy, dst, params=...)`/`RunnerParams`: создание стратегии из подготовленных данных до Client, жизненный цикл клиента, сборка адаптера рядом с Client и единая сборка движка. Просмотр счетов через reporting только в `run()`.
- **`serverless.py`** — обработчик Yandex Cloud Functions: `algoritm`/`src` с облачным значением по умолчанию COMPOSITE/BALANCED, `dst`/`token` из query string или окружения, подготовка до токена, запуск `Runner.run_sync()`.
- **`logging_config.py`** — локальная настройка логирования и JSON-форматтер для Yandex Cloud (`tinkoffBot`).
- **`handler.py`** в корне — тонкий entrypoint для облака (`handler.handler`).
- **Алгоритм синхронизации** (`sync_accounts`): свежий снимок стратегии → чтение назначения → полная стоимость с валютами → построение и проверка всей цели → расчёт продаж → расчёт покупок → единый порог от полной стоимости → отправка продаж перед покупками. ACCOUNT сначала применяет собственный резерв, затем `ratio = budget / total_src`, `quantity = ratio * source_quantity`; разницу до целых лотов округляет движок.
- Валюты исключаются из цели и стоимости источника ACCOUNT; валюты назначения входят в полную стоимость. Исполнитель не имеет резерва, листовые стратегии применяют его один раз к выделенному бюджету.
- Стратегии не импортируют SDK/grpc, адаптер, реестр, исполнителя, Runner или друг друга. Они зависят только от собственного порта, DTO и общих функций. Общие модели, контракт, triggers и reporting не импортируют SDK или конкретные стратегии. Reporting сохраняет отдельный клиентский путь назначения/счетов и путь собственного порта источника.
- Движок не импортирует реестр, адаптер, конкретные стратегии или `check_triggers`, не разбирает снимок источника и не читает конфиг. Конкретный адаптер выбирает Runner; SDK остаётся на границе чтения и исполнения.

### Контракт и добавление стратегии

Стратегия — небольшой класс без обязательного наследования от Protocol.
Конструктор получает подготовленные данные, не выполняет I/O и не хранит
порт/SDK-клиент. Контракт состоит из четырёх методов:

```python
strategy.load_snapshot(data)             # StrategyData, свежий снимок
strategy.build_target(snapshot, budget)  # TargetPortfolio, без SDK и отправки заявок
strategy.event_accounts(dst_account_id)  # tuple[str, ...]
strategy.should_rebalance(event, dst_account_id)  # bool
```

Снимок локален одному пересчёту; движок передаёт его обратно без разбора.
`budget` — полный выделенный Decimal-бюджет, у корня полная стоимость назначения.
Лист сам вычитает свой резерв; COMPOSITE передаёт детям budget * weight.
`event_accounts` возвращает непустой tuple уникальных непустых строк без
пробельных символов. `should_rebalance` возвращает строго bool: True для
пересчёта, False для пропуска. Оба метода не читают данные и не подписываются.
Проверка контракта проверяет только вызываемость методов, не вызывает их и не
читает резерв. Движок проверяет результаты событийных методов и открывает
один `data.position_events(accounts)`, сам сообщает каждый пропуск.
Рабочий поток не обязан завершаться. Движок выполняет начальную
синхронизацию до подписки и открывает следующую после окончания итератора,
`DataAccessError` порта или SDK `RequestError` исполнителя, включая ошибку
пересчёта по событию. В `run_sync()` события не запрашиваются, ошибки пробрасываются.

Порт предоставляет `get_portfolio(account_id)`, `find_instruments(query)`,
`get_instrument(uid)`, `get_last_prices(uids)`, `position_events(account_ids)`.
`PortfolioSnapshot.positions` хранит упорядоченные `PortfolioEntry` с Decimal
количествами штук и ценами за штуку, валютой и собственным `InstrumentType`.
`InstrumentMatch` содержит краткие UID/тикер/имя/тип/режим без валюты и лотности;
`InstrumentInfo` добавляет лотность, валюту и обязательный bool `api_trade_available`.
Адаптер берёт доступность из полных данных `Instrument.api_trade_available_flag`,
отклоняет не-bool; короткий флаг поиска не используется. Не обогащать поиск дополнительными
SDK-запросами. `PriceQuote` сохраняет цену и время; `PositionEvent` сохраняет
порядок блокировок и diagnostic_text. Не хранить SDK DTO/enum/raw_response в моделях.
Адаптер преобразует units/nano без округления, сохраняет порядок и дубликаты,
не определяет цели и не предоставляет торговых методов.

Ошибки конфигурации/данных — `ValueError`, включая `UnsupportedSourceError`;
они завершают вызов без retry/переподписки и без заявок ошибочного пересчёта.
Адаптер сообщает отсутствующие/неверные числа с полем/UID; INDEX проверяет знак
цены, лотность и совпадение метаданных. Транспортный `RequestError` переводится
в `DataAccessError` с исходной причиной, включая открытие и дальнейшее чтение
стрима. Ошибки программирования не маскировать и не возвращать пустую цель
при сбое источника. Заявки прошлых успешных пересчётов не отменяются.

`TargetPortfolio.quantities` — словарь UID → `Decimal` количества штук, не лотов и не дельт; `prices` — словарь UID → оценочная цена штуки (`Decimal`). Отсутствующий UID в непустой цели означает нулевую цель для имеющейся позиции. После `validate_target` пустой словарь количеств вызывает сообщение reporting на уровне INFO с назначением и причиной, затем ранний возврат без расчёта продаж, покупок, оценки объёма и отправки, включая debug. Исключение не выбрасывается, цикл продолжает работу; явные нули в непустой цели сохраняют прежний смысл продажи. Сбой источника должен быть исключением, а не пустой целью.

Обе карты цели должны быть словарями; ключи quantities — непустые строковые UID,
количества — конечные Decimal, включая отрицательные, дробные и нулевые.
Для каждого UID обязательна конечная Decimal-цена, даже для нулевого количества,
достигнутой цели или неторгуемого инструмента. `validate_target` отклоняет
повреждённые значения с полем/UID до любых заявок, включая debug. Нулевая
и отрицательная конечная цена допустимы в общем контракте; лишние цены игнорируются.

Цены нужны для `threshold`: продажи оцениваются по ценам назначения, покупки — по `target.prices` (для счёта это `current_price` того же снимка источника). Карты не объединяются. Сохранена оценка объёма через количество лотов без дополнительного умножения на лотность и строгое сравнение `volume > total_dst * threshold`: база — полная стоимость назначения с деньгами, до всех резервов и долей. BESTPRICE-заявки не передают цену исполнения. В debug проверка цели обязательна, денежная оценка объёма и отправка пропускаются.

Проверка пустой цели действует для всех стратегий. Пустая разница при достигнутой непустой цели не вызывает сообщение о пустой цели и остаётся обычным отсутствием заявок.

Для другого состава добавить JSON в `autorepeater/configs/` с уникальным `name`.
Для нового алгоритма добавить плоский модуль, тесты и одну регистрацию в
`strategies.py`: `register_algorithm('NAME', AlgorithmDefinition(prepare_source, create))`.
`prepare_source(src, context)` проверяет собственный src без SDK/создания стратегии и возвращает
непрозрачные данные; фабрика принимает только эти данные и создаёт объект без I/O.
Имя алгоритма непустое, без пробелов, точное; повтор регистрации запрещён,
совпадение с `name` JSON допустимо. Общий реестр не проверяет номера счетов
или конфиги. Импорт не выполняет I/O. CLI, облако, Runner и движок не менять.
Плоские Python-модули и нескрытые JSON автоматически включаются в архив;
проверять состав и запуск вне репозитория без сети. Тестовые регистрации не
добавлять в рабочий реестр.

`prepare_strategy(algoritm, src)` возвращает `PreparedStrategy` с фабрикой,
подготовленными данными и source_display. CLI/облако вызывают его один раз;
прямой пользователь Runner обязан сделать то же. `create_strategy(prepared)`
использует сохранённую фабрику без поиска регистрации/повторного чтения файлов
и выполняет `validate_strategy` до Client. Изменение файла между подготовкой
и созданием не меняет текущий запуск; новая подготовка увидит изменение.

`PreparationContext.prepare(algoritm, src)` готовит детей в порядке объявления.
Активные пары `(algoritm, src)` образуют стек; цикл вызывает ValueError с полным
путём до фабрик/Client. Соседний повтор допустим и готовится заново, глобального
кеша нет. Фабрика COMPOSITE создаёт детей через `strategy_contract.create_strategy`;
вся проверка контракта выполняется до открытия Client.

### ACCOUNT и COMPOSITE

ACCOUNT сохраняет ASCII-номер источника с ведущими нулями и читает только
`ACCOUNT_CONFIG_PATH` либо встроенный `configs/account/account.json`.
Корень — объект, `reserve` обязателен: конечная Decimal-строка в `[0, 1)`.
Встроенное значение `"0.01"`. Относительный путь считается от cwd; пустой,
отсутствующий или повреждённый файл вызывает ValueError с путём без fallback.
Настройки фиксируются при подготовке каждого вхождения. ACCOUNT вычитает
резерв перед прежним ratio; новой проверки положительности бюджета нет.
Стоимость исходных позиций квантуется по nano до суммирования, валюты исключены.

COMPOSITE выбирает непосредственные нескрытые JSON из `COMPOSITE_CONFIG_DIR`
либо `configs/composite/` относительно модуля. Схема: обязательное точное
`name` без пробельных символов, непустой массив `components`; каждый объект
содержит только `algoritm`, `src`, `weight`. Алгоритм — непустое точное имя
без пробельных символов, src — строка, не пустая и не состоящая из пробелов;
оба сохраняются без нормализации. Weight — конечная Decimal-строка в `(0, 1]`.
Сумма в объявленном порядке при точности 28 не больше 1; округлённое равенство
допустимо. Неизвестные поля запрещены в корне/компонентах, включая параметры
исполнения и reserve. Вложенность и повторные компоненты допустимы, циклы нет.
Пути INDEX, ACCOUNT и COMPOSITE независимы; каталог с неверным путём/без JSON
не подменяется встроенным. Общий каталог сохраняет прежние сообщения,
предупреждения по чужим файлам и ошибку по выбранному имени.

COMPOSITE получает положительный конечный Decimal-бюджет, передаёт детям
budget * weight без нормализации. При 100000 и долях 0.6/0.3 выделено 60000/30000,
10000 остаётся деньгами; с резервами 0.01/0.02 дети рассчитывают 59400/29400.
Вложенные доли умножаются до применения резерва листа. Снимки свежие и
последовательные, без гарантии единого времени. Все детские цели проверяются
до объединения; ошибка ребёнка отменяет весь пересчёт. Пустая цель ребёнка
даёт пустую общую цель с путём причины, без частичных заявок.
`TargetPortfolio.empty_reason` — строка или None только при пустых quantities.
Для одинакового UID количества складываются, цена равна максимуму цен детей,
содержащих UID в quantities. Лишние цены игнорируются, нулевые суммы сохраняются.
Один общий исполнитель считает разницу и threshold; дети не торгуют.

COMPOSITE объединяет счета детей в порядке первого появления, проверяя каждое
объявление. Передаёт событие всем детям без короткого замыкания, проверяет все
ответы bool, затем применяет any. Ошибочные tuple/bool вызывают ValueError
без retry. Подписки и сообщения о пропуске принадлежат общему движку.
Подробные поля и примеры формул см. [README.md](README.md).

### Контракт индексных стратегий

`select_index_config(name)` обнаруживает все нескрытые `*.json` непосредственно из
`autorepeater/configs/` относительно модуля либо из `INDEX_CONFIG_DIR`.
Совместимый `IMOEX_CONFIG_PATH` выбирает один файл вместо каталога; обе
переменные одновременно запрещены. Относительные пути считаются от рабочего
каталога. Пустой/отсутствующий каталог, пустой путь и конфликт переменных
вызывают ошибку без fallback внутри INDEX. Имена определяются полем `name`,
не именем файла. Каждый документ читается и валидируется независимо один раз.
Ошибка чужого файла или дубликат чужого имени даёт предупреждение с путём
и причиной. Ошибка выбранного файла, дубликат выбранного имени или отсутствие
имени завершают подготовку до SDK. Читаемое имя с ошибочным телом участвует
в дубликатах; имя из повреждённого JSON не восстанавливать по тексту/имени файла.
Неопознанный повреждённый файл получает предупреждение; при отсутствии выбранного
имени его путь входит в ошибку выбора. Единственный исправный сосед не подставляется.
`load_index_configs()` остаётся строгой отдельной проверкой всего набора.
Подготовка INDEX сохраняет выбранный `IndexConfig`; фабрика передаёт его в
`IndexStrategy(config)` без перечитывания. ACCOUNT и другие независимые алгоритмы
вообще не читают индексные файлы/настройки путей, независимо от формы src.
Глобального кеша конфигов нет, но конфиг фиксируется при создании объекта;
изменение базы требует согласованного обновления цен, индексных капитализаций
и справочных полей, затем перезапуска долгоживущего процесса.
Автоматического обновления состава и корпоративных действий нет.

Назначение каждого поля, единицы, влияние на расчёт и примеры IMOEX приведены
в [README.md](README.md). Не дублировать здесь перечень конкретных стратегий.
Кроме `min_position_value`, все поля обязательны, включая `reserve`:
`name` — непустая строка без пробельных символов, ASCII-цифры допустимы;
непустой `instruments`, уникальные непустые `ticker`;
десятичные поля только конечными строками. `reference_price` (руб./штука)
и `reference_index_capitalization` (руб.) положительны,
`effective_quantity` (штуки) неотрицательно, `free_float` и `weight_limit`
в `(0, 1]`, `reference_weight` в процентах `[0, 100]`,
`max_lot_weight_error` в долях `[0, 1)`, применяется только при ideal_lots < 1.
Сумма справочных процентов
не обязана быть ровно 100; нулевое справочное количество допустимо.
`min_position_value` — конечная неотрицательная Decimal-строка в валюте бюджета.
Значение IMOEX `"3000"`; отсутствие поля в старом явном конфиге означает
`"0"`, отключающий предварительный фильтр. JSON-числа, bool, NaN и Infinity
недопустимы. Запретов на другие валюты не добавлять.

`reserve` — конечная Decimal-строка в `[0, 1)`, доля полного выделенного бюджета,
не проценты: `"0.0005"` означает 0.05%, `"0.01"` означает 1%.
Отсутствие поля — ошибка без fallback; во внешние конфиги добавить reserve
явно. Резерв не зависит от числа инструментов и применяется к полному
выделенному INDEX бюджету. Калибровка использует только конфиг;
`--budgets` уже очищены от резерва.

Рабочая капитализация: `reference_index_capitalization * current_price / reference_price`.
Коэффициенты уже учтены в исходной индексной капитализации;
`effective_quantity`, `free_float`, `weight_limit`, `reference_weight`
справочные и повторно в формуле не применяются. Веса нормализуются по
кандидатам. Чистый расчётчик получает положительный конечный `Decimal` после
резерва; `IndexStrategy.build_target` сам вычитает резерв из полного бюджета.
Ранжировать весь состав по убыванию текущей капитализации, при равенстве по тикеру.
Один раз до перенормализации взять начальный префикс с
`budget * weight_in_FULL_INDEX >= min_position_value`, до первой бумаги ниже
минимума. Равенство включается; после округления фактическая сумма может быть ниже.
Затем нормализовать веса выбранного префикса и округлить идеальные лоты до
ближайшего целого, половины к чётному. При превышении бюджета отменять
округления вверх по наименьшему увеличению относительной ошибки, затем тикеру,
пока стоимость не поместится в бюджет.
Стоимость лота: `lot_cost = price * lot`;
ошибка: `abs(lots * lot_cost / budget - weight) / weight`.
Ноль фактических лотов всегда означает отказ; ошибка выше порога означает
отказ только при `ideal_lots < 1`. При `ideal_lots >= 1`, включая ровно один
лот, порог не применять. Проверять идеальное количество, не округлённое.
При первом отказе исключить бумагу и весь хвост, перенормализовать префикс
и повторить. Возврата исключённых внутри расчёта нет, предварительный фильтр
повторно не применяется; новый пересчёт начинает с полного состава.

Результат содержит `Decimal` количества штук, кратные лотности, и цены UID;
если исключены все, возвращается пустая цель с общим пропуском синхронизации.
Оценочная стоимость укладывается в бюджет, остаток остаётся деньгами;
исполнение BESTPRICE по изменившейся цене этим не гарантируется.
Отбор всегда даёт непрерывный префикс, но не гарантирует его конкретную длину
или монотонное расширение при увеличении бюджета. Ошибка относится к перенормализованным весам,
отклонение от полного индекса калибровка показывает отдельно.

Порог `max_lot_weight_error='0.05'` предварительный и настраивается в JSON,
не связан с `threshold` движка. Точное равенство вычисленных Decimal допускается;
при любом пороге конечная точность 28 может сдвинуть математическую границу
и изменить дальнейшие исключения. Epsilon и численные поправки не добавлять.

Для конфига с одним инструментом минимум позиции и ошибка веса не ограничивают
покупку. Цель равна максимальному целому числу лотов в бюджете после резерва по текущей
цене SDK. Уже имеющиеся бумаги учитываются движком, нехватка на один лот
даёт пустую цель без продажи портфеля. Это определяется исходным составом,
не результатом фильтрации многокомпонентного индекса. Положительные базовые
цена и капитализация нормализуются в вес 100%, не заменяют текущие котировки.
Порог отправки, торговый статус и debug не изменены; резерв не гарантирует
покрытие комиссии и движения цены исполнения.

Миграция контракта: `default_reserve`, `RunnerParams.reserve`, методы резерва
исполнителя и константа `DST_MONEY_RESERVED` удалены. Резерв — внутренние
настройки листа; движок не проверяет тип стратегии и не читает её конфиг.
Внешние INDEX-конфиги обязаны добавить reserve. Порог отправки теперь от полной
стоимости назначения до резервов, торговая арифметика листов сохранена.

Снимок заново разрешает весь состав через `data.find_instruments`,
`data.get_instrument` и пакетный `data.get_last_prices`; адаптер вызывает SDK.
Селектор требует точный `ticker` и тип `share`/`etf`, рассматривает все режимы
без белого списка и приоритета кодов TQBR/TQTF. По каждому совпадению читает
полные метаданные через порт; выбирает первый с `api_trade_available=True`
в порядке исходного ответа поиска. Несколько доступных вариантов дают WARNING
с выбранным UID/режимом и списком всех доступных вариантов, не ошибку.
Недоступные кандидаты и выбранный инструмент дают INFO через reporting.
Если доступных нет, ошибка с тикером и списком UID/режимов до котировок/заявок,
без fallback на недоступный инструмент. Не кешировать UID/режимы между снимками.
Метаданные по UID должны повторно подтвердить UID, тикер, тип и режим торгов;
ошибки UID, метаданных и лотности доступного кандидата указывают площадку.
SDK DTO в тестах задают `class_code` и полный `api_trade_available_flag` явно.
Некорректные/неполные данные вызывают ошибку, не частичную цель.
Цены положительны, могут относиться к прошлой сессии; валюта и время сохраняются.
Временно неторгуемые бумаги с ценой остаются в цели; статус проверяет движок.
Расчёт предполагает RUB, но специальных запретов других валют нет.
Конвертация и торговля валютами не реализованы.

INDEX объявляет только `(dst_account_id,)`; общий движок открывает подписку.
Пересчёт требует позицию назначения с деньгами или бумагами, все бумаги
и все денежные позиции без блокировок. Для остальных событий should_rebalance
возвращает False, движок сообщает пропуск. Котировки сами по себе пересчёт
не вызывают; локального таймера нет.

Калибровка: `python -m scripts.check_imoex_strategy` с явно предоставленным
`READ_ONLY_INVEST_TOKEN`. Опции: `--gross-values` (по умолчанию 100000 154000 300000),
`--budgets` (154000, без повторного резерва),
`--thresholds` (0.03 0.05 0.1), необязательный `--output` (путь JSON).
По умолчанию используется production API; `--sandbox` выбирает

## Облачный запуск

Yandex Cloud Functions может использовать корневой `handler.handler`. Обработчик запускает разовую синхронизацию (`run_sync`), а не долгоживущий stream-loop.

- Параметры запроса: `algoritm`, `src`, `dst`, `token`.
- `algoritm` берётся из query либо при отсутствии ключа из `ALGORITM`, затем из `DEFAULT_ALGORITM` (COMPOSITE). `src` берётся из query либо при отсутствии ключа из `SRC_ACCOUNT`, затем из `DEFAULT_SRC` (BALANCED) только для COMPOSITE. Для ACCOUNT, INDEX и других алгоритмов источник обязателен. Пустое/None/пробельное значение присутствующего ключа не заменяется окружением; пустое окружение также отклоняется до токена/Client.
- Без параметров выбора и их переменных окружения запускается COMPOSITE/BALANCED: INDEX/IMOEX `"0.684210526"`, INDEX/OBLG `"0.210526316"`, INDEX/GOLD `"0.105263158"`, в этом порядке, сумма точно 1. Компоненты применяют собственные резервы. Для индекса задавать `algoritm=INDEX&src=IMOEX` либо `ALGORITM=INDEX`, `SRC_ACCOUNT=IMOEX`; прежний выбор задаётся INDEX/TMON явно. Для счёта ACCOUNT и явный номер источника. Один src без алгоритма трактуется как имя JSON COMPOSITE. CLI по-прежнему требует оба параметра.
- Для токена сохранён fallback `INVEST_TOKEN` и совместимый `t_token`.
- Для `dst` сохранён прежний fallback через `DST_ACCOUNT` и `DEFAULT_DST_ACCOUNT`; fallback токена и формат успешного HTTP-ответа не менялись.
- Периодичность обеспечивает внешний облачный таймер. Обработчик не поддерживает debug: токен только для чтения вызывает ошибку при попытке выставить заявку, а не включает режим расчёта.
- `make claude-yandex-archive` создаёт `build/yandex-function.zip` с `main.py`, `handler.py`, всеми плоскими Python-модулями `autorepeater/`, нескрытыми JSON дерева `autorepeater/configs/` и `requirements.txt`. Новые модули/конфиги включаются автоматически. Внешний каталог автоматически не копируется. Диагностическая утилита, тесты, тестовые данные и окружения исключены. Изолированный тест проверяет CLI/облако с двумя индексными конфигами и default COMPOSITE/BALANCED, обязательные параметры, резервы и предупреждения; Client/сеть/торговля заблокированы.

## Конвенции

- Все денежные расчёты — **только `Decimal`** (units + nano/1e9), точность контекста 28. `float` допустим только на границе (CLI-параметры), там `Decimal(str(x))`.
- Константы `THRESHOLD`, `IMPORTANT` (кастомный уровень логирования = 25) объявлены в `constants.py`; резерв хранится в конфиге листовой стратегии.
- Пользовательский вывод через `logger.log(IMPORTANT, ...)` сосредоточен в `reporting.py`; `logger` объявлен в `logging_config.py`. Это не отладка.
- Тесты стратегии используют собственный порт/DTO; адаптер и SDK-интеграция используют autospec SDK с явными детерминированными DTO. Архитектурные AST-тесты закрепляют направления импортов; отдельный процесс блокирует импорт SDK при исполнении стратегий. Конечные тестовые стримы завершаются контролируемым исключением.

## Договорённости для разработки

1. Код проекта держим простым и плоским: общая ребалансировка в `autorepeater/repeater.py`, источник и его события в модуле стратегии, пользовательский вывод в `reporting.py`, CLI-вход в `main.py`, тесты в `test/`, общие контракты и DTO в плоских модулях. Не добавлять новые слои, пакеты и абстракции без явной пользы.
2. Денежные и количественные расчёты делать только через `Decimal`. `float` допустим только на границе CLI/API параметров, сразу переводить через `Decimal(str(value))`.
3. Константы `THRESHOLD`, `IMPORTANT` не переименовывать и не переносить без необходимости; резерв принадлежит листовым стратегиям и задаётся обязательным полем их конфигов.
4. Чистые общие функции расчёта и форматирования оставлять отдельными функциями верхнего уровня. SDK-логика назначения принадлежит движку и общим портфельным функциям; стратегия решает, какие данные читать через StrategyData, а SDK-запросы источника и подписки выполняет адаптер. В reporting допустимы read-only SDK-запросы через явно переданный клиент для просмотра счетов и поиска названий инструментов; повторно читать портфель ради вывода во время синхронизации нельзя. Reporting получает уже рассчитанные итоги, не определяет цель/бюджет/порог и не отправляет заявки. Не добавлять перехваты ошибок вывода, меняющие прежний проброс исключений.
5. Синхронизацию менять аккуратно: сначала рассчитываются продажи, затем покупки; отправка заявок происходит только после полного расчёта. Продажи должны идти раньше покупок.
6. `debug`-режим не должен отправлять заявки. Он может считать и логировать действия, но не вызывать `post_order`.
7. Пользовательский вывод робота писать функциями reporting через `logger.log(IMPORTANT, ...)`; диагностические данные и все пропуски торговли — через `logger.info(...)`. Логгер робота в обоих режимах настроен на INFO. Указывать причину пропуска, UID/тикер для инструмента, количества и лотность при округлении; не делать дополнительные SDK-запросы ради логов и не выводить токены. Чистые build_target/should_rebalance не логируют. В общем цикле транспортные ошибки порта ловить как `DataAccessError`, SDK исполнения как `RequestError`, логировать через `logger.error` в месте перехвата. `ValueError` данных не перехватывать для переподписки; стратегия передаёт ошибки наружу.
8. При работе с инструментами учитывать торговый статус: заявки выставлять только для `SECURITY_TRADING_STATUS_NORMAL_TRADING`.
9. Валюты источника ACCOUNT не участвуют в цели. Валюты назначения входят в полную стоимость для бюджета корня и threshold; каждый лист применяет свой резерв к выделенному бюджету.
10. Строковое форматирование денег сохранять совместимым с текущими тестами: без научной нотации, целые значения выводить с `.0`, nano-точность до 9 знаков.
11. Тесты писать на `pytest`. Для стратегий использовать `create_autospec(StrategyData, instance=True, spec_set=True)` и собственные DTO; без SDK в снимках и контрактных тестах. Тесты адаптера и интеграции SDK создают явные SDK DTO, сервисы подменять через стандартный `unittest.mock.create_autospec(inspect.unwrap(Service), instance=True, spec_set=True)` в существующей function-scoped фикстуре `client`. В SDK 1.51.0 экспортированные сервисы обёрнуты декоратором: `inspect.unwrap` обязателен, иначе autospec ошибочно требует `self`. Autospec проверяет сигнатуры вызовов, `spec_set=True` запрещает неизвестные атрибуты и методы. Контейнер `Mock(spec_set=[...])` разрешает только шесть используемых сервисов, включая `market_data` (`MarketDataService`); конструкторы SDK не вызывать. Ответы задавать через `return_value` или `side_effect`, без новых зависимостей и ручных Fake-сервисов. Котировки задавать явными `GetLastPricesResponse`, `LastPrice` и `Quotation`.
12. Для `mainflow` со стратегией счёта задавать конечную последовательность итераторов и исключений через `positions_stream.side_effect`, заканчивать её `TestException()` и вызывать цикл внутри `pytest.raises(TestException)`. Для ошибки во время чтения использовать конечный генератор с событием SDK и `RequestError`. Для общей стратегии использовать autospec `Strategy`, непрозрачный snapshot, `TargetPortfolio`, явный tuple event_accounts и bool should_rebalance; для порта — PositionEvent, DataAccessError и конечные итераторы. Проверять одну общую подписку и порядок счетов, вызов всех дочерних решений, переподписку после транспортной ошибки и проброс ValueError без retry. Каждый тест получает свежие моки; число и аргументы подписок и синхронизаций проверять явно. Рабочий поток не обязан завершаться.
13. Новую бизнес-логику покрывать тестами на расчётные функции отдельно от отправки заявок. Ожидания проверять в тестах через `assert_called_once_with`, `assert_not_called` или точное равенство `call_args_list` списку `call(...)`: это проверяет параметры, порядок и отсутствие лишних вызовов. Одного `assert_has_calls` без проверки общего числа вызовов недостаточно. Для изменений в `mainflow`/стримах добавлять детерминированные сценарии событий и восстановления; локальный `patch.object(..., autospec=True)` для `sync_accounts` допустим при отдельном покрытии отправки заявок.
14. Не добавлять новые зависимости без явной необходимости и согласования. Рабочие зависимости: `t-tech-investments`, `python-json-logger`. Для тестов и покрытия используются `pytest`, `pytest-cov`, `diff-cover`; инструменты проверок не включать в облачный `requirements.txt`.
15. Перед финалом изменений запускать полный `pytest --cov --cov-report=term-missing --cov-report=xml`, `coverage report --fail-under=90`, `diff-cover coverage.xml --compare-branch=origin/master --fail-under=90`, pylint всех отслеживаемых и новых Python-файлов, strict flake8 и `git diff --check`. Оба порога покрытия — 90%; не снижать их и не исключать рабочий код ради прохождения CI.
16. Стиль кода сохранять совместимым с текущими CI-настройками: обычный Python 3.12, без тяжёлой типизации, без dataclass-усложнений там, где хватает простой функции или небольшого DTO.
17. Комментарии и docstring можно писать по-русски или по-английски, но они должны объяснять смысл бизнес-правила, а не пересказывать строку кода.
18. Не исправлять опечатки в публичных/используемых именах вроде `postiton_to_string`, если это не отдельная согласованная задача с обновлением тестов.

### Пример фикстуры SDK-сервисов

Сокращённый пример существующей `client_tinvest`: `pytest`, SDK-классы (включая
`MarketDataService`) и `PostOrderResponse` уже импортированы в тестовом файле.
Ответы остальных методов задаются явными DTO в общей фикстуре или конкретном
тесте; для `market_data.get_last_prices` использовать `GetLastPricesResponse`
с явными `LastPrice` и `Quotation`, без сети и конструкторов сервисов.

```python
import inspect
from unittest.mock import Mock, create_autospec


@pytest.fixture(name='client')
def client_tinvest():
    services = {
        'instruments': InstrumentsService,
        'operations': OperationsService,
        'users': UsersService,
        'orders': OrdersService,
        'operations_stream': OperationsStreamService,
        'market_data': MarketDataService,
    }
    client = Mock(spec_set=list(services))
    for name, service in services.items():
        setattr(client, name, create_autospec(
            inspect.unwrap(service), instance=True, spec_set=True))
    client.orders.post_order.return_value = PostOrderResponse()
    client.operations_stream.positions_stream.side_effect = [iter(()), TestException()]
    return client
```
