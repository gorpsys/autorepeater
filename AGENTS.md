# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Автоповторитель сделок для Т-Инвестиций: приводит счёт назначения (dst) к цели стратегии, выбранной по обязательному `src`, через T-Invest API (`t-tech-investments`). Поддерживаются повторение брокерского счёта и индексная стратегия `IMOEX`. Локальный цикл использует `operations_stream.positions_stream`, облако выполняет разовый пересчёт.

## Запуск

```bash
export INVEST_TOKEN=...   # токен Т-Инвестиций, читается из окружения
python main.py -s <номер счёта или зарегистрированное имя> -d <id счёта назначения> \
    [--debug] [-t threshold] [-r reserve]
```

`--debug` — рассчитывает заявки, но не отправляет их. `threshold` (по умолчанию 0.004) — минимальная доля стоимости счёта, ниже которой синхронизация не выполняется. `reserve` — резерв на комиссии и округления из конфига стратегии; для повторения счёта по умолчанию 0.01. Явный `-r` переопределяет его на один запуск.

`src` обязателен: строка из ASCII-цифр выбирает `AccountStrategy`, сохраняя ведущие нули; иначе требуется точное имя из JSON-конфига или `NAMED_STRATEGIES`. Регистр и пробелы не нормализуются. Пустой/отсутствующий `src` вызывает `UnsupportedSourceError('src is required')`, неизвестный — `UnsupportedSourceError('unsupported src: ...')`. CLI и облачный обработчик проверяют источник до чтения токена, Runner — до создания SDK-клиента. Индексные имена берутся только из `name` конфигов; явный реестр по умолчанию пуст. Пример запуска: `python main.py -s IMOEX -d <id> --debug`. Значения по умолчанию выше взяты из `constants.py`; старые значения в CLI help пока не обновлены.

## Архитектура

Код разделён по слоям, точка входа остаётся в `main.py`:

- **`constants.py`** — константы `DST_MONEY_RESERVED`, `THRESHOLD`, `IMPORTANT` и настройка точности `Decimal`.
- **`money.py`** — чистые функции для `Decimal`, количества позиций и строкового форматирования денег/инструментов.
- **`portfolio.py`** — общее чтение портфеля `get_portfolio(client, account_id)` без вывода, DTO `TargetPortfolio` и проверка цен `validate_target`.
- **`reporting.py`** — пользовательские сообщения, просмотр счетов, форматирование позиций (`postiton_to_string`), поиск инструмента для вывода и `GetInstrumentException`.
- **`account_strategy.py`** — `AccountStrategy`: снимок источника без валют, ratio, целевые количества и цены, подписка на события источника и назначения.
- **`index_config.py`**, **`configs/*.json`** — схема, проверка и обнаружение индексных конфигов по полю `name`; встроенный IMOEX содержит 44 бумаги.
- **`index_strategy.py`** — `IndexStrategy`: свежие инструменты и котировки SDK, чистый `calculate_index_target`, бюджетное распределение лотов и события только назначения.
- **`scripts/check_imoex_strategy.py`** (от корня) — явно запускаемая калибровка без торговли, использует тот же чистый расчётчик.
- **`strategies.py`** — `validate_src`, селектор `create_strategy`, `NAMED_STRATEGIES` и `UnsupportedSourceError`; без SDK-запросов.
- **`triggers.py`** — специфичная для счёта проверка событий (`check_triggers`), вызываемая только `AccountStrategy`.
- **`orders.py`** — `OrderParams` и оценка объёма продаж/покупок по отдельным картам цен назначения/цели; используется максимум двух сумм.
- **`repeater.py`** — `AutoRepeater(client, strategy)`: бюджет назначения, проверка цели, расчёт/отправка заявок и общий цикл событий. `sync_accounts` и `mainflow` получают только `dst`.
- **`runner.py`** — `Runner`/`RunnerParams`: выбор стратегии до создания `t_tech.invest.Client`, жизненный цикл клиента и единая сборка движка с параметрами для `run()`/`run_sync()`. Просмотр всех счетов через reporting выполняется только в `run()`.
- **`serverless.py`** — обработчик Yandex Cloud Functions: читает `src`/`dst`/`token` из query string или окружения и запускает `Runner.run_sync()`.
- **`logging_config.py`** — локальная настройка логирования и JSON-форматтер для Yandex Cloud (`tinkoffBot`).
- **`handler.py`** в корне — тонкий entrypoint для облака (`handler.handler`).
- **Алгоритм синхронизации** (`sync_accounts`): свежий снимок стратегии → чтение назначения → бюджет с валютами после резерва → построение и проверка всей цели → расчёт продаж → расчёт покупок → проверка порога → отправка продаж перед покупками. Стратегия счёта вычисляет `ratio = budget / total_src`, затем `quantity = ratio * source_quantity`; целевые количества могут быть дробными, округление разницы до целых лотов выполняет движок.
- Валюты исключаются из цели и стоимости источника стратегией счёта; движок учитывает валюты назначения в бюджете и применяет резерв ровно один раз.
- Движок не импортирует селектор, `AccountStrategy` или `check_triggers`, не разбирает снимок источника. Общие модули и reporting не импортируют стратегии, Runner или движок; стратегия не вызывает движок.

### Контракт и добавление стратегии

Стратегия — небольшой класс без обязательного базового класса. Конструктор не обращается к SDK; контракт состоит из трёх методов:

```python
strategy.load_snapshot(client)           # свежий снимок перед каждой синхронизацией
strategy.build_target(snapshot, budget)  # TargetPortfolio, без SDK и отправки заявок
strategy.events(client, dst_account_id)  # один проход Iterable[bool]
```

Снимок локален одному пересчёту; движок передаёт его обратно без разбора. `budget` — Decimal-стоимость назначения после резерва. `events` выдаёт `True` для пересчёта и `False` для пропуска. Движок выполняет начальную синхронизацию до подписки и открывает следующую после завершения итератора или `RequestError`, включая ошибку синхронизации по событию. В `run_sync()` события не запрашиваются.

`TargetPortfolio.quantities` — словарь UID → `Decimal` количества штук, не лотов и не дельт; `prices` — словарь UID → оценочная цена штуки (`Decimal`). Отсутствующий UID в непустой цели означает нулевую цель для имеющейся позиции. После `validate_target` пустой словарь количеств вызывает сообщение reporting на уровне IMPORTANT с назначением и причиной, затем ранний возврат без расчёта продаж, покупок, оценки объёма и отправки, включая debug. Исключение не выбрасывается, цикл продолжает работу; явные нули в непустой цели сохраняют прежний смысл продажи. Сбой источника должен быть исключением, а не пустой целью.

Для каждого UID из `quantities` обязательна конечная Decimal-цена в `prices`, даже для нулевого количества, уже достигнутой цели или неторгуемого инструмента. `validate_target` отклоняет отсутствие цены, `None`, другой тип, NaN и Infinity с указанием UID до расчёта любых заявок, в том числе в debug. Нулевая цена допустима, положительность не проверяется; лишние ключи цен игнорируются.

Цены нужны для `threshold`: продажи оцениваются по ценам назначения, покупки — по `target.prices` (для счёта это `current_price` того же снимка источника). Карты не объединяются. Сохранена оценка объёма через количество лотов без дополнительного умножения на лотность и строгое сравнение `volume > budget * threshold`. BESTPRICE-заявки не передают цену исполнения. В debug проверка цели обязательна, денежная оценка объёма и отправка пропускаются.

Проверка пустой цели действует для всех стратегий. Пустая разница при достигнутой непустой цели не вызывает сообщение о пустой цели и остаётся обычным отсутствием заявок.

Для другого индексного состава или параметров добавить JSON в `autorepeater/configs/` с уникальным `name`: Python-код и реестр не менять. Для нового алгоритма добавить один плоский модуль в `autorepeater/`, импорт фабрики и запись `NAMED_STRATEGIES['NAME'] = factory` в `strategies.py`, а также тесты. Фабрика принимает исходный `src` и возвращает объект с этим контрактом без SDK-запросов. Имена алгоритмов не должны пересекаться с именами конфигов; конфликт вызывает ошибку. CLI, облачный обработчик, Runner и движок менять не требуется. Тестовая регистрация `TEST` существует только через monkeypatch. Дополнительные файлы алгоритма явно включать в облачный архив и проверять его состав; индексные JSON включаются автоматически.

### Контракт индексных стратегий

`load_index_configs()` читает все нескрытые `*.json` непосредственно из
`autorepeater/configs/` относительно модуля либо из `INDEX_CONFIG_DIR`.
Совместимый `IMOEX_CONFIG_PATH` выбирает один файл вместо каталога; обе
переменные одновременно запрещены. Относительные пути считаются от рабочего
каталога. Пустой/отсутствующий каталог, пустой путь, повреждённый конфиг или
повтор имени вызывают ошибку без fallback. Имена определяются полем `name`,
не именем файла. При каждом разрешении именованного `src` загружается весь
набор без SDK и без создания стратегий; импорт модулей не читает конфиги.
`create_strategy` передаёт выбранный `IndexConfig` в `IndexStrategy(config)`.
Валидация не создаёт стратегию. Для ASCII-номеров счетов конфиги не читаются.
Глобального кеша конфигов нет, но конфиг фиксируется при создании объекта;
изменение базы требует согласованного обновления цен, индексных капитализаций
и справочных полей, затем перезапуска долгоживущего процесса.
Автоматического обновления состава и корпоративных действий нет.

Назначение каждого поля, единицы, влияние на расчёт и примеры IMOEX приведены
в [README.md](README.md). Не дублировать здесь перечень конкретных стратегий.
Кроме `min_position_value` и `reserve`, все поля обязательны:
`name` — непустая строка без пробельных символов, не ASCII-номер счёта;
непустой `instruments`, уникальные непустые `ticker`;
десятичные поля только конечными строками. `reference_price` (руб./штука)
и `reference_index_capitalization` (руб.) положительны,
`effective_quantity` (штуки) неотрицательно, `free_float` и `weight_limit`
в `(0, 1]`, `reference_weight` в процентах `[0, 100]`,
`max_lot_weight_error` в долях `[0, 1)`, применяется только при ideal_lots < 1.
Сумма справочных процентов
не обязана быть ровно 100; нулевое справочное количество допустимо.
`min_position_value` — конечная неотрицательная Decimal-строка в валюте бюджета.
Значение IMOEX `"3000"`; отсутствие поля в старом явном конфиге означает
`"0"`, отключающий предварительный фильтр. JSON-числа, bool, NaN и Infinity
недопустимы. Запретов на другие валюты не добавлять.

`reserve` — конечная Decimal-строка в `[0, 1)`, доля стоимости назначения,
не проценты: `"0.0005"` означает 0.05%, `"0.01"` означает 1%.
Отсутствующее поле сохраняет старый резерв `DST_MONEY_RESERVED` (0.01);
в новых конфигах задавать явно. Резерв не зависит от числа инструментов.
Явный CLI `-r` переопределяет конфиг на один запуск, включая нулевое значение.
В облаке без CLI используется значение конфига. Калибровка применяет тот же
приоритет: явный `--reserve`, иначе конфиг; `--budgets` уже очищены от резерва.

Рабочая капитализация: `reference_index_capitalization * current_price / reference_price`.
Коэффициенты уже учтены в исходной индексной капитализации;
`effective_quantity`, `free_float`, `weight_limit`, `reference_weight`
справочные и повторно в формуле не применяются. Веса нормализуются по
кандидатам. Бюджет положительный конечный `Decimal`, резерв уже вычтен движком.
Ранжировать весь состав по убыванию текущей капитализации, при равенстве по тикеру.
Один раз до перенормализации взять начальный префикс с
`budget * weight_in_FULL_INDEX >= min_position_value`, до первой бумаги ниже
минимума. Равенство включается; после округления фактическая сумма может быть ниже.
Затем нормализовать веса выбранного префикса и округлить идеальные лоты до
ближайшего целого, половины к чётному. При превышении бюджета отменять
округления вверх по наименьшему увеличению относительной ошибки, затем тикеру,
пока стоимость не поместится в бюджет.
Стоимость лота: `lot_cost = price * lot`;
ошибка: `abs(lots * lot_cost / budget - weight) / weight`.
Ноль фактических лотов всегда означает отказ; ошибка выше порога означает
отказ только при `ideal_lots < 1`. При `ideal_lots >= 1`, включая ровно один
лот, порог не применять. Проверять идеальное количество, не округлённое.
При первом отказе исключить бумагу и весь хвост, перенормализовать префикс
и повторить. Возврата исключённых внутри расчёта нет, предварительный фильтр
повторно не применяется; новый пересчёт начинает с полного состава.

Результат содержит `Decimal` количества штук, кратные лотности, и цены UID;
если исключены все, возвращается пустая цель с общим пропуском синхронизации.
Оценочная стоимость укладывается в бюджет, остаток остаётся деньгами;
исполнение BESTPRICE по изменившейся цене этим не гарантируется.
Отбор всегда даёт непрерывный префикс, но не гарантирует его конкретную длину
или монотонное расширение при увеличении бюджета. Ошибка относится к перенормализованным весам,
отклонение от полного индекса калибровка показывает отдельно.

Порог `max_lot_weight_error='0.05'` предварительный и настраивается в JSON,
не связан с `threshold` движка. Точное равенство вычисленных Decimal допускается;
при любом пороге конечная точность 28 может сдвинуть математическую границу
и изменить дальнейшие исключения. Epsilon и численные поправки не добавлять.

Для конфига с одним инструментом минимум позиции и ошибка веса не ограничивают
покупку. Цель равна максимальному целому числу лотов в бюджете после резерва по текущей
цене SDK. Уже имеющиеся бумаги учитываются движком, нехватка на один лот
даёт пустую цель без продажи портфеля. Это определяется исходным составом,
не результатом фильтрации многокомпонентного индекса. Положительные базовые
цена и капитализация нормализуются в вес 100%, не заменяют текущие котировки.
Порог отправки, торговый статус и debug не изменены; резерв не гарантирует
покрытие комиссии и движения цены исполнения.

Опциональное свойство стратегии `default_reserve` задаёт исходный Decimal-резерв
для движка. При отсутствии свойства применяется `DST_MONEY_RESERVED`.
IndexStrategy возвращает `config.reserve`; явный `set_reserve` переопределяет
значение. Движок не проверяет тип стратегии и не читает её конфиг.

Снимок заново разрешает весь состав через `find_instrument`,
`get_instrument_by` и пакетный `market_data.get_last_prices`.
Селектор требует точный `ticker`, пару `share`/`TQBR` для акций либо
`etf`/`TQTF` для фондов, ровно одно совпадение среди этих основных режимов.
Нет fallback на другие площадки и
фильтрации по `api_trade_available_flag`. Метаданные по UID должны повторно
подтвердить UID, тикер, тип и режим торгов; ошибки разрешения, UID, метаданных
и лотности указывают площадку. SDK DTO в тестах задают `class_code` явно.
Некорректные/неполные данные вызывают ошибку, не частичную цель.
Цены положительны, могут относиться к прошлой сессии; валюта и время сохраняются.
Временно неторгуемые бумаги с ценой остаются в цели; статус проверяет движок.
Расчёт предполагает RUB, но специальных запретов других валют нет.
Конвертация и торговля валютами не реализованы.

События IMOEX подписаны только на `accounts=[dst_account_id]`.
Пересчёт требует позицию назначения с деньгами или бумагами, все бумаги
и все денежные позиции без блокировок. Остальные события логируются и дают
`False`. Котировки сами по себе пересчёт не вызывают; локального таймера нет.

Калибровка: `python -m scripts.check_imoex_strategy` с явно предоставленным
`READ_ONLY_INVEST_TOKEN`. Опции: `--gross-values` (по умолчанию 100000 154000 300000),
`--reserve` (явное переопределение конфига), `--budgets` (154000, без повторного резерва),
`--thresholds` (0.03 0.05 0.1), необязательный `--output` (путь JSON).

## Облачный запуск

Yandex Cloud Functions может использовать корневой `handler.handler`. Обработчик запускает разовую синхронизацию (`run_sync`), а не долгоживущий stream-loop.

- Параметры запроса: `src`, `dst`, `token`.
- Переменные окружения как fallback: `SRC_ACCOUNT`, `DST_ACCOUNT`, `INVEST_TOKEN`; для совместимости со старой облачной функцией поддерживается `t_token`.
- Для `src` сохранён облачный fallback: query string → `SRC_ACCOUNT` → `DEFAULT_SRC_ACCOUNT` (TMON). По умолчанию запускается одноинструментный конфиг TMON с резервом 0.0005 (0.05%). Если ключ `src` присутствует в запросе, его пустое/None/пробельное значение вызывает ошибку без fallback на окружение. Пустой `SRC_ACCOUNT` также отклоняется. Для другого индекса явно задавать `src=IMOEX` или `SRC_ACCOUNT=IMOEX`.
- Для `dst` сохранён прежний fallback через `DST_ACCOUNT` и `DEFAULT_DST_ACCOUNT`; fallback токена и формат успешного HTTP-ответа не менялись.
- Периодичность обеспечивает внешний облачный таймер. Обработчик не поддерживает debug: токен только для чтения вызывает ошибку при попытке выставить заявку, а не включает режим расчёта.
- `make claude-yandex-archive` создаёт `build/yandex-function.zip` с `handler.py`, Python-модулями `autorepeater/`, всеми нескрытыми `autorepeater/configs/*.json` и `requirements.txt`. Внешний каталог автоматически не копируется. Диагностическая утилита, тесты и тестовые данные исключены.

## Конвенции

- Все денежные расчёты — **только `Decimal`** (units + nano/1e9), точность контекста 28. `float` допустим только на границе (CLI-параметры), там `Decimal(str(x))`.
- Константы `DST_MONEY_RESERVED`, `THRESHOLD`, `IMPORTANT` (кастомный уровень логирования = 25) объявлены вверху модуля и импортируются тестами — не переименовывать молча.
- Пользовательский вывод через `logger.log(IMPORTANT, ...)` сосредоточен в `reporting.py`; `logger` объявлен в `logging_config.py`. Это не отладка.
- Тесты в `test/test_autorepeater.py` создают настоящие SDK DTO (`MoneyValue`, `Quotation`, `PortfolioPosition`, `Instrument`, ответы и события) с явными детерминированными данными. Сервисы SDK подменяются через `unittest.mock.create_autospec`; ожидания задаются в тестах. Конечный сценарий стрима завершается через `TestException`, проверяемый с `pytest.raises`.

## Договорённости для разработки

1. Код проекта держим простым и плоским: общая ребалансировка в `autorepeater/repeater.py`, источник и его события в модуле стратегии, пользовательский вывод в `reporting.py`, CLI-вход в `main.py`, тесты в `test/test_autorepeater.py`. Не добавлять новые слои, пакеты и абстракции без явной пользы.
2. Денежные и количественные расчёты делать только через `Decimal`. `float` допустим только на границе CLI/API параметров, сразу переводить через `Decimal(str(value))`.
3. Константы `DST_MONEY_RESERVED`, `THRESHOLD`, `IMPORTANT` не переименовывать и не переносить без необходимости: их импортируют тесты и они являются частью текущего контракта модуля.
4. Чистые общие функции расчёта и форматирования оставлять отдельными функциями верхнего уровня. SDK-логика назначения принадлежит движку и общим портфельным функциям, чтение источника и подписка — стратегии. В reporting допустимы read-only SDK-запросы через явно переданный клиент для просмотра счетов и поиска названий инструментов; повторно читать портфель ради вывода во время синхронизации нельзя. Reporting получает уже рассчитанные итоги, не определяет цель/бюджет/порог и не отправляет заявки. Не добавлять перехваты ошибок вывода, меняющие прежний проброс исключений.
5. Синхронизацию менять аккуратно: сначала рассчитываются продажи, затем покупки; отправка заявок происходит только после полного расчёта. Продажи должны идти раньше покупок.
6. `debug`-режим не должен отправлять заявки. Он может считать и логировать действия, но не вызывать `post_order`.
7. Пользовательский вывод робота писать функциями reporting через `logger.log(IMPORTANT, ...)`. В общем цикле ошибки SDK ловить как `RequestError` и логировать через `logger.error` в месте перехвата; стратегия передаёт ошибки наружу для переподписки.
8. При работе с инструментами учитывать торговый статус: заявки выставлять только для `SECURITY_TRADING_STATUS_NORMAL_TRADING`.
9. Валюты на счёте-источнике не участвуют в расчёте портфеля. Валюты на счёте назначения учитываются в общей стоимости, после чего применяется `reserve`.
10. Строковое форматирование денег сохранять совместимым с текущими тестами: без научной нотации, целые значения выводить с `.0`, nano-точность до 9 знаков.
11. Тесты писать на `pytest`. SDK DTO создавать явно, сервисы подменять через стандартный `unittest.mock.create_autospec(inspect.unwrap(Service), instance=True, spec_set=True)` в существующей function-scoped фикстуре `client`. В SDK 1.51.0 экспортированные сервисы обёрнуты декоратором: `inspect.unwrap` обязателен, иначе autospec ошибочно требует `self`. Autospec проверяет сигнатуры вызовов, `spec_set=True` запрещает неизвестные атрибуты и методы. Контейнер `Mock(spec_set=[...])` разрешает только шесть используемых сервисов, включая `market_data` (`MarketDataService`); конструкторы SDK не вызывать. Ответы задавать через `return_value` или `side_effect`, без новых зависимостей и ручных Fake-сервисов. Котировки задавать явными `GetLastPricesResponse`, `LastPrice` и `Quotation`.

Для `mainflow` со стратегией счёта задавать конечную последовательность итераторов и исключений через `positions_stream.side_effect`, заканчивать её `TestException()` и вызывать цикл внутри `pytest.raises(TestException)`. Для ошибки во время чтения использовать конечный генератор, который выдаёт явное событие SDK и выбрасывает `RequestError`. Каждый тест получает свежие моки; число и аргументы подписок и синхронизаций проверять явно. Сохранять регрессию RequestError из пересчёта по событию с последующей переподпиской и успешной синхронизацией.

Ожидания проверять в тестах через `assert_called_once_with`, `assert_not_called` или точное равенство `call_args_list` списку `call(...)`: это проверяет параметры, порядок и отсутствие лишних вызовов. Для изменений в `mainflow`/стримах добавлять детерминированные сценарии событий и восстановления; локальный `patch.object(..., autospec=True)` для `sync_accounts` допустим при отдельном покрытии отправки заявок.

### Пример фикстуры SDK-сервисов

Сокращённый пример существующей `client_tinvest`: `pytest`, SDK-классы (включая

import inspect
from unittest.mock import Mock, create_autospec


@pytest.fixture(name='client')
def client_tinvest():

        'instruments': InstrumentsService,
        'operations': OperationsService,

    client.orders.post_order.return_value = PostOrderResponse()
    client.operations_stream.positions_stream.side_effect = [iter(()), TestException()]
    return client
