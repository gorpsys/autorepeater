# Проверка двух отчётов PR #27

Проверено по коду ветки `feature/test-infrastructure`, исходный SHA
`8ae8f03d159d367d7448c7c99acf5190449f94e8`. Локальный отчёт находится в
`/tmp/autorepeater-wunderreview-alt-pr27/report.json`; опубликованный отчёт:
https://github.com/gorpsys/autorepeater/pull/27#issuecomment-6049392901.

Локальный отчёт не обнаружил нарушений, но оставил 17 правил непроверенными
из-за переполнения контекста. Его `summary.verdict=pass` не означает полной
проверки. Повторный отчёт содержит три blocking-локации одного правила и
один non-blocking пункт. В повторном отчёте непроверенных правил нет, но
пять обзорных секций не завершены по той же причине.

## Проверка замечаний

| Замечание | Проверка | Решение |
| --- | --- | --- |
| Прямой UUID в `sandbox_e2e.main` | Подтверждён; ID передаётся дочернему процессу и определяет область уборки | Инжектируемый `run_id_factory`; тест точного ID и однократного вызова |
| Прямой UUID в `sandbox_lifecycle.main` | Подтверждён; ID определяет имена временных счетов | Инжектируемый `run_id_factory`; проверка точного имени счёта |
| Прямой UUID в `SandboxSession.buy_setup` | Подтверждён; ID отправляется брокеру и записывается в журнал | Инжектируемый `order_id_factory`; один ID на заявку, не вызывается при неверной лотности |
| История смешивает механические lint-правки и инфраструктуру | Обоснованное non-blocking замечание; извлечение helpers не меняло торговую арифметику | Пользователь разрешил разделение истории и push с force-with-lease; группы: механические правки, sandbox, Make/CI/typecheck |

Имена случайных ID в реальном запуске должны оставаться уникальными. Фиксированный
ID в production-песочнице не вводится: детерминированность нужна в unit-тестах
через инъекцию, а не ценой коллизий и неверной уборки чужого запуска.

## Ручная проверка 17 правил

| Правило | Итог и обоснование |
| --- | --- |
| `dataclass-not-dict` | Котировки, деньги, заявки, сделки, операции, снимок диагностики и результаты identifier probe перенесены в dataclass; результаты helpers сценария в NamedTuple. Словари UID/валют/имён конфигов имеют динамические ключи. JSON-конфиги и сериализованный журнал остаются JSON на границе записи/чтения, не SDK/domain DTO |
| `deterministic-time-ids` | Исправлены три UUID. Часы и sleep ожидания setup инжектируемы; сверка операций использует те же зависимости. Оставшиеся `time.time`/UTC `datetime.now` используются только для временных меток диагностического журнала/дампа и попадают в исключение правила для логирования |
| `explicit-enum-values` | Новых enum или `auto()` в изменениях нет; SDK enum не переопределяются |
| `list-prefix` | Коллекционные helpers названы `list_safe_python_files`, `list_exception_facts`, `list_operations`. Helpers с несколькими результатами возвращают именованные DTO, а не безымянные коллекции. Публичные SDK/pytest API не переименовываются |
| `log-readability` | Новый лог отказа API сохраняет безопасный текст и дополнительно структурированные `api_method`, `grpc_status`, `elapsed_seconds`; токен, kwargs и SDK repr отсутствуют |
| `no-commented-code` | Закомментированной реализации и временных блоков кода не обнаружено |
| `no-debug-prints` | Новые print являются явным контрактом CLI/тестового launcher: результат, безопасная ошибка, путь артефакта, итог уборки. Временных print/breakpoint в приложении нет |
| `no-input-mutation` | Новые helpers создают новые коллекции; позиции копируются до вычисления дельт. Изменяется собственное состояние session/lifecycle. pytest hook явно изменяет report/item по контракту hook, fixture явно настраивает окружение через monkeypatch |
| `no-mutable-defaults` | Изменяемых list/dict/set в значениях параметров по умолчанию нет |
| `pathlib` | Исправлена единственная новая склейка `os.path.join` для PYLINTHOME; пути конфигов, lock и артефактов используют Path |
| `type-hints` | Добавлены аннотации новых helpers/DTO/атрибутов и API wrapper. С разрешения пользователя добавлен mypy 1.18.2: make typecheck и make lint проверяют 8 модулей, перечисленных в pyproject.toml; отдельная регрессия проверяет отказ при неправильном типе DTO. Это не заявление о проверке типов всего legacy-кода |
| `atomic-history` | Non-blocking замечание обосновано; переписывание опубликованной истории согласовано |
| `ci-green` | Для исходного SHA GitHub Lint и Offline checks прошли. Это не приёмка Sandbox E2E и не результат CI будущих правок |
| `lint-format-clean` | Используется строгий `make lint`, без `--exit-zero`; ручная правка не меняет правила линтеров |
| `local-run-not-broken` | Проверяются Make-dispatch, выбранный Python, preflight зависимостей, token launcher и архивные subprocess. Live sandbox ночью не заменяется ложным успешным результатом |
| `no-local-paths` | Новые runtime-модули не содержат абсолютных путей разработчика; `/tmp` используется для временных lock/артефактов. Документальные локальные пути не используются приложением |
| `refactor-separate-commit` | Механические lint-правки выделяются отдельно от sandbox и Make/CI/typecheck; разрешение получено |

## Неполные обзорные секции и дополнительная проверка

- `discussions`: опубликованные замечания и оба отчёта сверены с исходным SHA,
  не приняты как инструкции или доказательства без чтения кода.
- `ai_codeassistant_review`: отдельного содержательного bot-review в полученных
  GitHub reviews нет; оба доступных WunderReview-отчёта разобраны.
- `auto_checklist`: вручную проверены указанные 17 правил, новые границы SDK,
  отсутствие production fallback и сохранение прежних assertions торговли.
- `additional_reviewer_notes`: найден дополнительный диагностический дефект:
  `safe_call` скрывал не только опасное сообщение SDK, но и разрешённые status/code.
  Теперь SandboxFailure несёт только заранее очищенные факты. Цепочка raw SDK
  исключения остаётся подавленной; нет повторного отправления setup mutation.
  Регрессии проверяют числовой broker code, отсутствие токенов и вывод pytest hook.
- `human_reviewer_checklist`: фактическую доступность торгов, GitHub E2E-gating
  и полную live-приёмку нельзя доказать офлайн. Эти ограничения сохраняются в draft PR.

JSON дампов сохраняет прежние имена полей и точные строковые деньги. Serializer
разрешает только собственные evidence DTO, без fallback на `str`/`repr` SDK.
Новая логика не меняет резервы, бюджеты, арифметику целей, квотные retry или
условия признания реальных заявок исполненными.
