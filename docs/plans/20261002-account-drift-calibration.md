# Калибровка допуска ACCOUNT под прежний threshold

## Решение

Для будущего встроенного ACCOUNT-конфига принять
`allocation_drift_limit = "0.0092"`, то есть **0.92%** отклонения состава.
Строгое превышение допуска разрешает внутреннюю ребалансировку.
Покупки и обязательное сокращение выделенного бюджета этим допуском
не ограничиваются, как согласовано в [основном плане](20261002133314-rebalance-policy-implementation-plan.md).

Это стартовый эмпирический параметр для новой политики, не историческое значение.
Рабочий конфиг и исполнитель не изменены: нынешний загрузчик ACCOUNT
ещё не поддерживает новый параметр. Он будет добавлен при реализации плана.

## Что сравнивалось

Старый критерий: движок рассчитает хотя бы один лот продажи, а оценка
max(покупки, продажи) строго больше полной стоимости назначения * 0.004.
Оценка взята из действующего `get_max_sum_positions_price`
(`autorepeater/orders.py:18`): цена штуки умножается на количество лотов,
без умножения на лотность. Для калибровки эта особенность не исправлялась.
Расчёт лотных дельт воспроизводит `AutoRepeater.calc_sell_positions`
(`autorepeater/repeater.py:49`) и `calc_buy_positions` (строка 96).

Новый критерий: есть хотя бы один лот продажи и половина суммы модулей
разниц нормированных весов вложенной части строго больше допуска.
Фактические и контрольные веса оцениваются по одной карте цен.
Новая покупочная ветка не сравнивается со старым threshold: по требованию
пользователя она должна работать при любой возможности исполнимой покупки.

Бюджет контрольной цели равен стоимости имеющихся бумаг. Для ACCOUNT её
нормированные веса совпадают с весами источника: резерв масштабирует все
количества одним коэффициентом и сокращается при нормировке.
Цели рассчитаны самим `AccountStrategy.build_target`, включая прежнюю
поквантную оценку стоимости источника, без альтернативной торговой арифметики.

## Данные и сценарии

- Реальные сохранённые котировки и лотности 44 акций из
  `test/data/imoex_snapshot.json`, полученного 29 сентября 2026 года.
  В наборе 24 инструмента с лотом 1, 14 с лотом 10, 5 с лотом 100 и 1 с лотом 1000.
- **Составы исходных счетов модельные**, не прочитанные из счёта 2193248994.
  Три равновесные по числу случаев группы: 12 крупнейших с весами по справочной
  капитализации, все 44 с такими весами, все 44 с равными весами.
  Данные состава взяты из `autorepeater/configs/imoex.json`; усечение хвоста
  и индексный расчётчик не используются, это калибровка алгоритма ACCOUNT.
- Номинальные бюджеты назначения: 50000, 63000, 100000, 154000, 300000,
  650000, 1000000 и 3000000 рублей. Начальные количества округляются к лотам.
  После округления фактический полный бюджет определяется как стоимость
  имеющихся бумаг / 0.99; денежный остаток ровно 1% этого бюджета.
  Поэтому фактический бюджет может отличаться от номинальной точки.
- Источник моделируется на 10 млн рублей с целыми лотами. Затем его количества
  независимо меняются в пределах 0%, 0.1%, 0.2%, 0.4%, 0.8%, 1.6%, 3.2%,
  6.4%, 12.8% и 25.6% и снова округляются до целых лотов, минимум один лот.
  Это изменения состава источника, не одинаковый рост или падение рынка.
- Для каждого случая цены меняются независимо в пределах +/-10%, шаг 0.1%.
  Одна и та же цена используется для источника и назначения.
- По 100 случайных случаев на каждую комбинацию группы, бюджета и амплитуды:
  24000 для подбора, seed 20261002; ещё 24000 для проверки, seed 20261003.
- Python 3.12, Decimal с точностью 28. API, токены и отправка заявок не используются.

## Критерий подбора

Минимизировать суммарное число расхождений решения о продаже на выборке подбора.
Дополнительные разрешения и пропущенные разрешения имеют одинаковый вес.
Порог перебирается по точным наблюдаемым значениям отклонения; при равной
ошибке выбирать больший, более консервативный порог. Отсутствие исполнимых
лотов продажи не считается разрешением фактической продажи в обоих режимах.

Оптимум на выборке подбора: `0.00923135090710188633709617736`.
Округление до шага `0.0001` даёт `0.0092`. Проверочная выборка не использовалась
для выбора порога. На выборке подбора у округлённого порога 1990 расхождений
из 24000, совпадение 91.7083%.

## Независимая проверка

| Решение старого критерия | Новый разрешает продажи | Новый не разрешает продажи |
| --- | ---: | ---: |
| Разрешает | 13540 | 724 |
| Не разрешает | 1355 | 8381 |

Итог: 21921 совпадение из 24000, **91.3375%**. В 5.6458% всех случаев
новый критерий дополнительно разрешает продажу, в 3.0167% не разрешает
продажу, которую разрешал прежний. Это доли модельных сценариев, не прогноз
частоты реальных торгов, комиссий или вероятности финансового убытка.

| Состав | Собственный оптимум на подборе, % | Совпадение на проверке общего допуска 0.92%, % |
| --- | ---: | ---: |
| 12 крупнейших, веса по капитализации | 0.5259 | 90.6125 |
| Все 44, веса по капитализации | 0.9315 | 91.6250 |

Прямой перенос `0.004` в новый допуск дал бы на проверке 3086 расхождений
(совпадение 87.1417%) вместо 2079 при выбранном значении.

## Почему точного эквивалента нет

При стоимости бумаг 10000 рублей, резерве 1%, ценах двух бумаг по 1 рублю,
целевых весах 50/50 и фактических количествах 5100/4900 отклонение равно 1%.
Если лот равен 1, старая оценка продажи 100 рублей превосходит порог
40.4040... рублей. Если лот равен 10, старая оценка тех же 100 штук равна
10 рублям, а при лоте 100 — 1 рублю: старый критерий не срабатывает.
Новое отклонение во всех трёх случаях одинаково. Один числовой допуск
не может точно воспроизвести старые решения для разных лотностей.

Дополнительно влияют округление дельт и различие покупки/продажи,
денежного остатка и композиционной ошибки. Калибровка намеренно исключает
пополнение, сокращение бюджета, пересечения COMPOSITE, неприписанные позиции,
неторгуемые инструменты, блокировки и задержку исполнения: это отдельные
условия новой политики, а не перевод threshold в допуск.

После появления обезличенного реального снимка ACCOUNT повторить сравнение
с тем же критерием. До этого выбранное число является модельным стартовым
значением, а не проверенным пределом для счёта 2193248994.

## Воспроизводимость и проверки

Сохранён [JSON-отчёт](20261002-account-drift-calibration.json) с параметрами,
матрицами решений, разбивкой по бюджетам и SHA-256 входных файлов.
Локальный расчётчик: `/tmp/autorepeater-account-drift-calibration.py`.
Независимая проверка: `/tmp/autorepeater-account-drift-audit.py`.
Эти временные скрипты не входят в облачный архив и исчезнут при очистке /tmp.

```bash
PYTHONPATH=. /tmp/autorepeater-install-check/bin/python /tmp/autorepeater-account-drift-calibration.py
PYTHONPATH=. /tmp/autorepeater-install-check/bin/python /tmp/autorepeater-account-drift-audit.py
```

Проверено совпадение калибровочного расчёта со старым движком для 300
независимых сценариев с лотами 1/10/100/1000; SDK-сервис подменён через
create_autospec без сети. Подбор оптимума отдельно проверен полным перебором
кандидатов на 100 случайных небольших наборах. Все проверки прошли.
