# Проверка валюты портфеля в песочнице

Диагностический PR по issue #11. Не предназначен для мержа или production-деплоя.

Отдельный workflow `Sandbox portfolio currency probe` запускается при открытии
и обновлении PR из ветки `test/sandbox-portfolio-currency` владельцем репозитория.
Повторный запуск доступен через Re-run jobs. Основной Sandbox E2E и его
обязательный статус не изменены. Оба workflow используют общую очередь песочницы.

Каталог облигаций запрашивается через sandbox API. В отчёт попадают все облигации
с номиналом USD: тикер, название, UID, класс торгов, номинал и валюта расчётов.
Для первых 20 кандидатов с разрешёнными покупками API проверяется текущая
торговый статус и доступность BESTPRICE. Первыми проверяются замещающие выпуски
Газпром капитал ЗО27-1-Д (`RU000A1056U0`) и Лукойл ЗО-27 (`RU000A1059P4`).
Два первых доступных кандидата с номиналом не больше 1 000 USD используются в сценариях
BOND1 и BOND2. Среди них могут быть замещающие облигации с расчётами в RUB:
номинал USD не означает цену позиции в USD. При рублёвых расчётах опыт проверяет
поведение таких облигаций, но не заменяет опыт с долларовой валютой расчётов.
Иностранные акции не используются. Рублёвая контрольная бумага — SBER.

Сценарий MIXED отдельно ищет облигации с расчётами в CNY, USD или EUR
(CNY проверяется первым), не подменяя их выпусками с расчётами в RUB.
На временный счёт запрашивается пополнение в валюте выбранной облигации
и в RUB. Явный отказ 30258 на иностранную валюту записывается с WARNING;
другие ошибки не обходятся. Затем выполняются те же три покупки.
Для успеха MIXED должен подтвердить в одном снимке владение обеими бумагами
с разными валютами расчётов. Одного иностранного номинала или валюты денежного
остатка недостаточно. Разные валюты цен в ответе записываются отдельно:
если сервер пересчитывает цены в одну валюту, это результат опыта, не ошибка теста.
Недоступный инструмент, закрытые торги или ошибка API делают соответствующий
сценарий неуспешным; это не доказательство ошибки валютного контракта.

Каждый сценарий открывает временный sandbox-счёт и пополняет его виртуальными
100 000 USD и 1 000 000 RUB. Если USD-пополнение явно отклонено с кодом 30258,
записывает отказ, выводит WARNING и продолжает с пополнением только RUB;
таймауты и другие ошибки таким способом не обходятся. Затем покупает один лот облигации, один лот
SBER и ещё один лот той же облигации. После каждой покупки GetPortfolio
читается без валюты запроса, затем с RUB, USD и EUR. После сценария счёт закрывается;
при прерывании предусмотрена ограниченная очистка текущего запуска.

SDK 1.51.0 не передаёт параметр currency через обычную обёртку get_portfolio.
Явные варианты отправляются напрямую через тот же GetPortfolio RPC на канале
SandboxClient, с конечным тайм-аутом. Production endpoint и production-токен
не используются. Неопределённые результаты отправки заявки не повторяются.

Артефакт `portfolio-probe-<run>-<attempt>` содержит JSON по тикерам и JUnit.
В JSON: валюта инструмента, класс торгов, текущий торговый статус и разрешения,
отдельные строки бумаг без удаления повторов UID,
количества и цены units/nano, валюты итоговых оценок, фазы покупки и результат
очистки. Классификация цены: instrument_currency, request_currency,
mixed_or_other или inconclusive. Отличие от предположения не является ошибкой теста:
эксперимент собирает факты, не навязывает валютную семантику серверу.

Отсутствие повторов UID в нескольких снимках не доказывает их невозможность
во всём API. Наблюдения sandbox также не гарантируют идентичное поведение production.
Raw SDK-ответы, metadata, токены и полный run.log в артефакты не включаются.

Если BESTPRICE запрещён, но статус инструмента `NORMAL_TRADING`, тест использует
лимитную заявку по лучшей цене продажи из стакана глубиной 1. Цена облигации
передаётся как `PRICE_TYPE_POINT` (проценты номинала), не как сумма в RUB. Пустой стакан
останавливает сценарий до заявки. Ожидание исполнения ограничено 30 секундами;
оставшаяся активной заявка отменяется перед завершением с ошибкой.

Промежуточный результат: в прогоне
[38685601034](https://github.com/gorpsys/autorepeater/actions/runs/38685601034)
Росэксимбанк БО-001P-01 (`RU000A0JX2M2`) прошёл все три фазы. Во всех 12 снимках
цены и итоги оставались в RUB, включая запросы USD/EUR; повторов UID не было.
Это наблюдение относится к данному sandbox-прогону, не ко всем инструментам API.
Второй кандидат Russia 2027 вернул общий отказ 30049: точная причина из кода
не следует. Ограничение номинала исключает крупные выпуски из следующего опыта
с фиксированным тестовым пополнением.

Замещающие выпуски успешно проверены в прогоне
[38686467557](https://github.com/gorpsys/autorepeater/actions/runs/38686467557):
Газпром капитал ЗО27-1-Д (`RU000A1056U0`) и Лукойл ЗО-27 (`RU000A1059P4`).
Четыре лимитные покупки облигаций и две BESTPRICE-покупки SBER исполнены полностью.
В 24 снимках цены позиций и итоговые оценки оставались в RUB независимо от
запрошенной валюты. После повторной покупки количество облигаций выросло до двух,
но повторных строк одного UID не появилось. Оба временных счёта закрыты.
Смешанные валюты цен этим опытом не проверены: все купленные инструменты
рассчитываются в RUB. Выводы не являются гарантией поведения production.

Локальный запуск, только с sandbox-токеном в окружении и без параллельного CI-прогона:

```bash
make setup
.venv/bin/python -m test.sandbox_portfolio_live
```

Обычный `make test` эти live-сценарии не собирает. Офлайн-проверки диагностики:

```bash
.venv/bin/python -m pytest test/test_portfolio_probe.py
```
